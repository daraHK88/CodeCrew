# Coding workflow

Complete the current user goal with the smallest reliable workflow. Preserve unrelated work, secrets, financial semantics and access controls. Current instructions and verified source take precedence over saved memory and skill defaults. A complete implementation brief authorizes ordinary reversible choices: do not ask for design confirmation, approval of a routine plan, or permission to continue merely because a skill suggests it. Ask only when missing information materially affects correctness, scope or an irreversible action.

For a small, clear change, locate the owning code, edit directly and run the narrow useful check. Do not create a team, task board, classifier request, design reference, DESIGN.md or completion judge for a copy, icon, color, spacing or similarly local edit. Keep cheap reader routing for routine inspection and tool use.

For substantial work, supervise scoped assignments with Objective, Inputs, Scope, Acceptance, Verification and Stop conditions. Include the overall goal and constraints in the first team_dispatch; update team_checkpoint when the goal or next actions change. Dispatch ready independent work together, use approved worker profiles and keep fresh worker context. Integrate worktree commits and verify the actual diff and requirements before accepting tasks. Workers report results; only the supervisor accepts them. Use current task revisions from status. Cancel and drain failed work before replacing it; inspect retained files before retrying uncertain edits.

For a substantial new UI, use the automatically selected design skill and configured UI model. Establish a coherent direction from the existing brand, real content and primary action. Prioritize hierarchy, readable type, useful density, consistent spacing, clear interaction and platform conventions. Build real controls and data states. Verify desktop and narrow mobile rendering, keyboard and focus behavior, overflow, and the primary interactions. Use a refinement skill for polishing an existing interface. A complete brief does not need a design approval round or compulsory mockups. Small visual edits keep the direct path.

Read bounded source excerpts and reuse findings. Batch independent safe tools, keep dependent edits ordered, and avoid repeated catalog or file reads. Use skill_search for missing relevant guidance; do not reload identical instructions already retained. Use coding_decide only for a bounded ambiguous choice, never to approve passing checks. Start long independent checks as background jobs and continue useful work. Their completion resumes the owner; collect results before reporting, without polling loops. Waiting is not success.

Keep durable preferences in general memory and project facts in the workspace brief: goal, constraints, decisions, progress, checks and next actions. Refresh changed facts without transcripts or secrets. Coordinator checkpoints, tasks and evidence survive history compaction; compaction is not lossless. Treat historical partial work as context and never resume it over a newer incompatible request. Report actual checks, blockers and limits concisely; do not claim speed, cost or quality gains without measurements.
