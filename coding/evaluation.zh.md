# 编码评估

[English](evaluation.md) | 中文

本地评估通过实际 CodeCrew 桌面 Host 和已配置模型账户执行，使用隔离、无外部依赖的 JavaScript 示例仓库。评估对象是借鉴 [Super-agent](https://github.com/deepseek-ai/dsh-superagent-prototype) 的分派实现，不是 DeepSeek 原型或其基准结果。

## 任务与结果

小任务修复时长格式中的秒数补零，保留不受小时限制的分钟数。Luna 在 13.76 秒内完成，调用五次工具，没有 worker 或工具错误。原有测试及十项独立边界断言通过。

大任务实现带验证的 JSON 任务解析器、保序并发映射器及 runner 整合。Worktree worker 独立提交模块，主管审查和整合提交、补充测试，再凭持久证据验收。两次运行的 worker 执行区间均有重叠。

| 观察项 | 初次运行 | 最终运行 |
| --- | ---: | ---: |
| 耗时 | 196.44 秒 | 122.05 秒 |
| 主管工具调用 | 64 | 32 |
| 主管工具错误 | 6 | 0 |
| Agent 编写的仓库测试通过数 | 10 | 20 |
| 独立补充测试通过数 | 15 | 15 |
| 全部 agent 报告的总 token | 2,019,020 | 1,218,024 |
| 全部 agent 缓存读取 token | 1,898,368 | 1,075,072 |
| 全部 agent 报告的未缓存输入 token | 109,529 | 135,336 |
| 全部 agent 输出 token | 11,123 | 7,616 |

初次运行由 Luna 主管协调两名 Sol worker。最终配置在分派时将 Lead 切换到获准 planner profile（Astra）；解析器使用 Sol，映射器使用 Luna。整合后 Lead 返回 Luna，全局默认仍为 Luna。首次启动还发现 worktree 服务未挂载，已在统计这两次完成运行之前修正。分派状态增加当前任务版本，以减少无谓的验收重试。

## 代码质量与限制

独立检查覆盖无效配置、重复及未去除空白的 ID、非有限数值、映射器参数验证、不可变输入、输出顺序、并发上限、首次失败后停止接收新任务、等待已启动调用结束、保留假值拒绝原因，以及 runner 在调用 handler 前验证配置。最终代码全部通过。源码审查发现模块简短、沿用项目约定且未添加依赖；并发映射器使用独立失败标记，避免将假值拒绝误判为成功。

这只是一组任务，模型路由不同，模型及缓存变化未受控制。报告的总 token 包含缓存输入，不能证明费用降低：未缓存输入增加，模型价格也不同。结果证明路由可用及定向检查通过，不代表普遍提速、可直接用于生产或稳定达到高级工程师水准。实际仓库仍需自身测试、类型检查、整合审查及相关 UI 验证。Worker 报告仍是主管需要验证的陈述。
