# 工作成员上下文作用域

[English](guide.md) | 中文

## 变更

Agent Teams 工作成员不再接收仅限 Lead 的工具模式、模型配置目录或完整协调器检查点。自己的任务、项目指令和权限仍然可用。整个界面的自动设计工作流由 Lead 执行；其他本地技能规则和显式加载仍适用于成员。创建、列出和更新任务的结果省略 `description` 和 `verification`；`team_task_get` 仍可返回完整值。这改变的是面向模型的工具结果，不是已存储的任务记录。

`skills/select-automatic` 瀑布事件现在同时处理本地规则命中和未命中的情况。其 `next()` 返回本地选择，未命中时返回空列表。

分派任务现在可记录主管角色与确切技能名称；任务可记录不可变的父工作包。旧 Team 记录仍然有效，旧版严格 Team 读取器会拒绝包含这些新可选字段的记录，因此记录分层工作后不支持降级。投影检查点用新缓存版本从日志重建。编码覆盖配置禁用源码重建监听，但保留插件图传递；重建代码须完整重启 App 与 Host 后生效。

## 迁移

需要向成员提供更小的编码工具集时，在 `tool-agent-team` 配置中将 `workerTools` 设为已加载全局工具名称的白名单；空列表保留继承工具。作用域内的 Team 与决策工具不变。

1. 由 Lead 分派任务并配置模型路由。只向成员提供相关路径、接口、约束和验收检查；需要额外技能时显式加载。
2. 集成需要完整任务描述或验证时，读取 `team_task_get`。使用回执中的 ID 和修订号进行更新。
3. 更新自动技能选择器：等待 `next()`，并保留非空结果，除非有意覆盖。在该作用域中返回空列表即可抑制自动选择。
4. 确认成员请求包含自己的任务和执行工具，而 Lead 保留分派、模型选择和检查点控制。现有会话和任务数据无需迁移。

5. 分层工作先用 `role: supervisor` 与 `isolation: shared` 分派工作包，再以 `parent_task_id` 创建子任务，子任务路径保持在父包范围内。省略 `skills` 则自动选择，也可提供确切允许名称。确认子任务独立运行，且父包在验收全部子任务前不能报告就绪。
6. 对通过完整重建更新的 profile 设置 `client-hmr.config.watchBuilds: false`。重建前退出，完成后重新启动；有意使用 Web 实时开发时保留默认监听。
